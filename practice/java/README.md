| 큐·스택·힙 | 기본 3문제 구현 확인. 괄호의 조기 실패 처리 재점검 |

| 수준 | 판정 기준 |
|---|---|
| L0 | 접근과 구현 구조를 거의 잡지 못함 |
| L1 | 힌트를 통해 접근을 이해하거나 구현 |
| L2 | 방향은 독립 설계했으나 구현·디버깅에서 도움 필요 |
| L3 | 힌트 없이 구현하고 제공 테스트와 직접 만든 반례를 통과하며 로직을 설명함 |

누적 기록은 아직 미평가다. 날짜별 최초 시도의 L0~L3가 기록된 문제만 분모에 넣고 L3 수와 비율을 함께 갱신한다. 재풀이 변화는 따로 기록한다.

## 매일의 루틴과 다음 세트 조정

1. 입력·출력·예외·종료 조건을 적고 작은 예를 손으로 추적한다.
2. 시그니처, 변수와 자료구조, 메인 처리 순서를 설계한다.
3. 직접 구현한다. 막히면 시도한 접근을 먼저 기록하고 힌트를 한 단계씩 연다.
4. 제공 테스트와 최소 반례를 실행하고 날짜별 복습 기록에 시간, 도움, 수준을 남긴다.
5. 힌트를 사용했거나 실수가 반복된 문제는 이틀 뒤 빈 메서드에서 다시 구현한다.

다음 세트를 만들기 전 최신 풀이와 복습표를 함께 읽는다. 동일 유형에서 두 문제 연속 L3면 상태·조건·복합 알고리즘·성능 제한 중 하나를 더한다. L0~L1이 반복되면 실패 원인을 분류하고 최소 구현 → 새로운 유사 문제 → 재검증 순으로 보완한다. L2라면 설계에는 상태표, 문법에는 짧은 API 연습, 경계 오류에는 최소 반례, 성능에는 입력 크기별 연산 수 추정을 배정한다. 기록이 없으면 승급 판정을 보류한다.

풀이 리뷰에서는 문제 해석, 관리한 상태, 자료구조 선택, 종료 조건과 인덱스, 최소 실패 입력 순으로 확인한 뒤 수정에 필요한 힌트 하나를 준다. 완성 풀이는 학습자가 요청할 때 제공한다.

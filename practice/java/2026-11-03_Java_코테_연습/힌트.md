# 막힌 문제만 한 단계씩 열기

## 1. 관측소 신호 순위

<details>
<summary>Hint 1 — 접근 방향</summary>

총합이 같은 두 관측소의 순서를 결정하려면 무엇을 더 기억해야 할까?

</details>

<details>
<summary>Hint 2 — 자료구조와 처리 순서</summary>

관측소별 총합과 건수를 따로 기록한다. 비교 기준마다 오름·내림 방향을 표시해 본다.

</details>

<details>
<summary>Hint 3 — 의사코드</summary>

기록마다 이름별 합(long)과 건수를 갱신 → 이름을 한 번씩 모음 → 합, 건수, 이름 중 처음 다른 기준으로 순서 결정.

</details>

## 2. 교정실의 빈 슬롯

<details>
<summary>Hint 1 — 접근 방향</summary>

도착한 시각과 실제로 선택되는 시각을 구별하자.

</details>

<details>
<summary>Hint 2 — 자료구조와 처리 순서</summary>

도착 목록을 읽는 위치와 대기 중인 요청의 우선순위를 분리한다. 같은 시각에 들어온 요청도 후보가 된다.

</details>

<details>
<summary>Hint 3 — 의사코드</summary>

각 슬롯에서 해당 시각까지 새로 도착한 번호를 모두 힙에 추가 → 비었으면 유휴, 아니면 긴급도·번호 기준 첫 요청 하나를 꺼내 기록.

</details>

## 3. 교정 테이프의 봉인

<details>
<summary>Hint 1 — 접근 방향</summary>

봉인이 열렸을 때와 닫힌 후, 삭제할 수 있는 범위가 어떻게 달라질까?

</details>

<details>
<summary>Hint 2 — 자료구조와 처리 순서</summary>

StringBuilder와 봉인을 열 때의 길이를 담는 스택을 고려한다. 내용을 복사하지 않고 길이를 줄일 수 있다.

</details>

<details>
<summary>Hint 3 — 의사코드</summary>

문자마다 기록·삭제·열기·닫기 중 하나를 수행 → 닫을 봉인이 없으면 즉시 오류 → 취소 때 시작 길이 복원 → 끝나면 남은 봉인을 안쪽부터 취소.

</details>

## 4. 연속 항차 감사 구간

<details>
<summary>Hint 1 — 접근 방향</summary>

한 구간이 이미 예산을 넘었다. 오른쪽에 무료 항차를 더하면 유효해질까? 횟수 제한에서도 생각해 보자.

</details>

<details>
<summary>Hint 2 — 자료구조와 처리 순서</summary>

비용이 음수가 없으므로 오른쪽 끝을 늘릴 때 왼쪽 끝을 되돌릴 필요가 없다. 구간 합과 항구별 횟수를 함께 유지한다.

</details>

<details>
<summary>Hint 3 — 의사코드</summary>

오른쪽 항차 추가 → 두 제한 중 하나라도 위반하면 왼쪽 항차를 제거하며 두 통계를 갱신 → 유효한 비어 있지 않은 구간이 이전 최장보다 길 때만 양 끝 기록.

</details>
